# SuperStory 개발본부 — 프로젝트 보드

전사 프로젝트 포트폴리오를 한 장으로 보는 웹 보드와, 그 운영 기준·프로젝트별 상세 문서를 묶은 정적 사이트입니다.
Vercel에 폴더째 올리면 바로 동작하며, 빌드 과정은 없습니다.

- 기준일: 2026-09-29 · v1.0
- 운영: 전병모(내용 결정) + Claude(반영·스냅샷)
- 갱신 리듬: 신규 건은 생기는 즉시 / 정기 갱신은 **목요일 저녁** → **금요일 주간회의** 안건 1번 "보드 훑기"

---

## 1. 이 보드가 해결하려는 문제

프로젝트가 짧게, 계속 생기는 구조에서 **얘기됐던 일이 잊히는 누수**를 막는 것이 목적입니다.
원칙은 세 가지입니다.

1. **이름이 붙는 순간 등록한다** — 한 줄짜리 구상이어도 등록한다. 모르는 칸은 "미정"으로 둔다.
2. **삭제하지 않고 휴면시킨다** — 움직임이 없으면 ⚪ 휴면으로 내리고, 끝나면 ✅ 종료로 둔다.
3. **사람별 R&R은 입력하지 않고 파생시킨다** — 개인 칸은 프로젝트 행과 마일스톤에서 모인 결과다.

보드는 **포트폴리오 레이어**입니다. 세부 태스크·버그는 지금처럼 Jira(안국주·홍수화 관리)에 두며, 보드는 Jira를 대체하지 않습니다.

## 3. 배포 방법

### 처음 올릴 때

1. https://vercel.com/new 접속 (계정: `byungmochuns-projects`)
2. `deploy` 폴더를 **통째로** 드래그 앤 드롭
3. 프로젝트 이름 지정 — 예: `superstory-dev-board` → 주소 `https://superstory-dev-board.vercel.app/`
4. Deploy

### 갱신해서 다시 올릴 때

- 드래그 앤 드롭 방식이면: 같은 프로젝트의 **Deployments → 새 배포**로 수정된 폴더를 다시 올립니다. 새 프로젝트를 만들면 주소가 바뀌니 주의.
- GitHub 연동 방식이면: 저장소에 커밋·푸시하면 자동 배포됩니다. 주간 갱신이 반복되므로 장기적으로는 이 방식이 편합니다.

### vercel.json 설정

| 설정 | 효과 |
|---|---|
| `cleanUrls: true` | `.html` 없이도 열림 (`/management_standard`) |
| `Cache-Control: max-age=0, must-revalidate` | 갱신본이 캐시에 막히지 않고 바로 보임 |
| `X-Robots-Tag: noindex, nofollow` | 검색엔진 노출 차단 |

### 공개 범위 — 반드시 확인

보드에는 **사업 제안 현황, 계약 상태, 인원별 담당**이 들어 있습니다.

- noindex는 검색 노출만 막을 뿐, **링크를 아는 사람은 누구나 열 수 있습니다.** `files/`의 기획서·엑셀도 같은 조건으로 내려받을 수 있습니다.
- 사내 전용으로 막으려면 Vercel **Settings → Deployment Protection**을 켭니다.
  - 켜면 Vercel 팀 계정이 없는 사람은 열 수 없습니다.
  - 다른 허브 페이지에 iframe으로 넣으면 403이 납니다 (과거 node-editor 사례와 같은 증상).
- 공유 대상(팀원 전원 / 본부장급 / 대표 보고용)을 먼저 정하고 켤지 결정하세요.
- 수면 아래 유지 건(비공개 휴면 1건)은 보드 본문에 이름을 쓰지 않고 각주로만 둡니다. 이 원칙은 공개 범위와 무관하게 유지합니다.

## 4. 보드 읽는 법

### 4.1 프로젝트 리스트 열

| 열 | 의미 |
|---|---|
| 분류 | A 동화·앱 / B IP·콘텐츠 / C 메인 개발 / D 사업(제안·PoC·회신 대기) / E 계약·인프라 |
| 상태 | 🟢 진행 · 🟡 대기 · ⚪ 휴면 · ✅ 완료 |
| 오너 / 백업·확인 | 책임자. "(초안)"·"미정"은 금요일 회의 확정 대상 |
| 다음 액션 | 지금 이 건에서 다음에 일어나야 할 한 가지 |
| 팔로업 | **다음에 다시 들여다볼 날짜** (아래 설명) |
| 상세 | R&R 문서, 허브, 프로토타입 등 링크. "R&R 작성 대상/예정"은 상세 문서가 아직 없음 |

### 4.2 팔로업과 목표일의 차이

- **목표일**(마일스톤) = "언제까지 끝낸다"는 약속
- **팔로업**(보드) = "언제 다시 확인한다"는 점검 예약

회신을 기다리는 건(넷플릭스 제안, WYD, 방산 등)은 우리가 끝낼 수 없으니 목표일을 못 씁니다. 대신 팔로업을 걸어두면 그날 회의에서 반드시 다시 올라옵니다. 그래서 **🟡 대기 건은 팔로업 날짜가 필수**입니다.
마일스톤 문서가 붙은 건(신데렐라)은 그 문서의 날짜가 팔로업을 대신하고, 완료 건은 "—"입니다.

음영(■) 칸 = 아직 기입 안 된 날짜입니다.

### 4.3 인원별 R&R 종합

하단 8명 카드(전병모 / 개발팀 이상훈·안국주·홍수화·이순형 / 그래픽팀 박인성·이규선·유성현)는 **직접 입력하지 않고** 위 리스트와 마일스톤에서 파생합니다.

| 칸 | 기준 |
|---|---|
| 담당 중 | 오늘이 마일스톤 구간(시작일~목표일) 안에 있는 일 = 요즘 맡은 일 |
| 임박 | 이번 주 목표일·팔로업이 도래하는 일 = 지금 급한 일 |
| 최근 완료 | 최근 ✅ 처리된 일 (다음 갱신 때 정리) |

프로젝트 행의 오너가 바뀌면 카드도 같이 바뀌어야 합니다. 갱신 시 Claude가 함께 맞춥니다.

## 5. 운영 절차

### 5.1 주간 갱신 (목요일 저녁)

전병모가 Claude에게 변경분만 한 줄씩 전달합니다.

```
보드 갱신:
- 신데렐라 v1.3.1 Android 제출 완료, 수정 2건은 ○○·○○
- 아이스크림 회신 옴, 다음 액션 미팅 일정 잡기, 팔로업 10/8
- 신규: ○○○ 문의 (D, 오너 미정)
```

Claude가 하는 일:

1. 보드 행(상태·오너·다음 액션·팔로업) 수정
2. 관련 상세 문서(신데렐라 버전 로그 등) 동기화
3. 인원 카드 재정리
4. 주간 스냅샷 보관 (그 주 상태를 날짜 찍어 남김)
5. 수정된 `deploy` 폴더 제공 → 전병모가 Vercel에 재배포

### 5.2 금요일 주간회의

- 안건 1번 "보드 훑기" — 특히 **팔로업 날짜가 도래한 🟡 대기 건**
- "미정·(초안)" 오너 확정
- 결정된 내용은 다음 목요일 갱신에 반영 (**구두 변경 금지** — 보드 갱신으로 성립)

### 5.3 신규 프로젝트 등록 (1분)

필드 5개만 채우면 됩니다: **이름 · 분류(A~E) · 오너 · 다음 액션 · 팔로업 날짜**.
판단이 애매하면 일단 등록합니다. 신규 건은 원칙적으로 **D(사업)** 로 들어옵니다.

### 5.4 수명주기

```
인입(D) ──계약·착수 확정──▶ 승격(A/B/C) + R&R 문서 부착
   │                              │
   └─팔로업에 움직임 없음──▶ ⚪ 휴면 (삭제 금지)
                                  │
                        완료·공식 드랍 ──▶ ✅ 종료 (한 줄 사유)
```

## 6. 상세 문서(R&R·마일스톤) 작성 규칙 — 신데렐라 양식

승격된 프로젝트는 신데렐라 문서와 같은 구조로 상세 페이지를 붙입니다.
현재 작성 대상: **어린왕자 80주년, 퀵게임 게임팩토리, 결(GYEOL)**.

### 6.1 구성

1. **R&R** — 역할 / 담당 / 책임 범위. 모든 트랙은 담당 1인 + 확인 1인. 일정 소유자(산정·갱신)와 검증자(지연 확인)를 분리
2. **마일스톤** — `#` / 마일스톤 / **시작일** / **목표일** / 담당·확인 / 완료 판정 기준
3. **버전 로그** (앱처럼 버전이 있는 경우)
4. 백업 체제·운영 규칙 (필요 시)

### 6.2 마일스톤 표기 규칙

- **날짜 칸에는 날짜만** 적습니다 (`9/30`, `10/08`). 모르면 ■.
- 날짜를 정한 **산정 규칙은 완료 판정 기준 맨 앞에 `[기준: …]` 태그**로 적습니다.
  - 예: `[기준: 목표일 = 리뷰 제출일 +8일, 재제출 시 재계산]`
- **시작일과 목표일을 모두** 적습니다. 인원별 R&R이 이 구간에서 파생되기 때문입니다.
- 구간이 아닌 단발 판단(예: 착수 판단)은 시작일 "—", 목표일만 적습니다.
- 완료되면 마일스톤 이름 옆에 ✅, 판정란에 완료일과 경위를 남깁니다.
- 버전이 바뀌어도 **마일스톤을 새로 만들지 않습니다.** 대상 버전만 갱신하고 이력은 버전 로그에 남깁니다.
- 번호를 재배열하면 **문서 내부와 보드의 M번호 참조를 모두 같이 고칩니다.**

### 6.3 신데렐라 현재 마일스톤 (참고)

| # | 마일스톤 | 시작 | 목표 | 기준 |
|---|---|---|---|---|
| M1 | Android 심사 통과 (v1.3.1) | 9/30 | 10/08 | 리뷰 제출일 +8일 |
| M2 | 정식 서비스 런칭 (rollout 20→50→100%) | 9/30 | 10/08 | 잠정, M1 통과와 동시 런칭 목표 · 시작 조건 = 퀄리티업 완료 + 대표 승인 |
| M3 | iOS 심사 제출 (v1.3.1) | 9/30 | 10/02 | Android 제출 +2일 이내 |
| M4 | 약관·방침 업로드 + 스토어 폼 | — | 9/07 ✅ | 완료 |
| M5 | 백업 체제 가동 (안국주 온보딩) | 10/01 | 10/07 | 10/01 + 근무일 5일 |
| M6 | 후속 동화 1종 착수 판단 | — | ■ | 블랭크 |
| M7~M9 | 버전 정책 서버 / 체크 모듈 / In-App Updates | ■ | ■ | 후속 동화 프로젝트 착수와 함께 |

주의 사항 두 가지:

- **통과 ≠ 런칭** — 퀄리티업 기간에는 Play Console **관리형 게시(managed publishing)** 를 켜 두어야 승인 즉시 자동 게시되는 사고를 막습니다.
- M7~M9 이연으로 신데렐라는 **버전 체크 없이 운영**됩니다(강제 업데이트 수단 없음). 후속 착수가 늦어지면 이 공백도 길어집니다.

### 6.4 버전 로그 규칙

- **스토어에 제출하는 순간 행을 만듭니다.** 통과일·출시일은 확인되는 날 채웁니다.
- 교체·철회된 버전은 지우지 않고 비고에 종결 사유를 남깁니다.
- 출시일(런칭) = **서비스 개시일**. Android는 rollout 시작일(100% 도달일은 비고), iOS는 "출시됨" 확인일.
- 통과했지만 게시 보류 중인 버전은 통과일만 채우고 출시일은 비워 둡니다(정상 상태).
- 퀄리티업 지시는 **반영될 다음 버전 행의 비고에 누적** 기재합니다.
- (정책 서버 가동 후) reviewVersions 등록은 제출 시, 제거는 게시 확인 후.

```html
  <td><span class="lb D">D</span></td>          <!-- 분류: A~E -->
  <td>프로젝트 이름</td>
  <td class="st">🟡 대기</td>                     <!-- 🟢 진행 / 🟡 대기 / ⚪ 휴면 / ✅ 완료 -->
  <td>오너 / 백업</td>
  <td>다음 액션</td>
  <td class="date">■</td>                         <!-- 팔로업: 날짜 또는 ■ -->
  <td class="todo">—</td>                         <!-- 상세: 링크 또는 — -->
</tr>
```

상세 칸에 링크를 넣을 때:

```html
<td><a class="doc" href="https://…vercel.app/" target="_blank" rel="noopener">링크 이름</a></td>
```

같은 분류끼리 모아 A → E 순서를 유지하고, 행을 더하거나 빼면 헤더의 "24건"과 "프로젝트 리스트 (24)" 숫자도 고칩니다.

### 7.2 인원 카드 구조

```html
<div class="person">
```

### 7.3 편집 후 확인

- 브라우저에서 로컬로 열어 표가 깨지지 않는지 확인
- 링크 3종(보드↔기준↔신데렐라) 클릭 확인
- 보드 오너 칸과 인원 카드가 서로 맞는지 확인

## 8. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 루트 주소가 404 | `index.html`이 없음 (파일명을 `project_board.html`로 올림) | 보드 파일을 `index.html`로 올리기 |
| "← 프로젝트 보드" 클릭 시 404 | 세 파일 중 일부만 배포 | `deploy` 폴더 전체를 함께 배포 |
| 갱신했는데 옛날 내용이 보임 | 브라우저 캐시 | 강력 새로고침(Ctrl/Cmd+Shift+R). vercel.json이 포함됐는지 확인 |
| 팀원이 열면 로그인 화면 / 403 | Deployment Protection 켜짐 | 공유 범위에 맞게 설정 조정 |
| 다른 허브 iframe에서 안 보임 | Deployment Protection 또는 X-Frame 제한 | 보호 해제 또는 새 창 링크(카드)로 연결 |
| 새로 배포했더니 주소가 바뀜 | 새 프로젝트로 생성함 | 기존 프로젝트에 재배포, 또는 Domains에서 별칭 추가 |
