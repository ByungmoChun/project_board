퀵게임 게임팩토리 — 파이프라인 운영 규칙 · 사이클 1

담당·R&R보다 먼저 정하는 시간 규칙과 관문 · 10/02 결정(A안, 10/05 착수) 반영
작성: 2026-10-02 · 개발본부 · 초안 v0.2 분류: B라인 (IP·콘텐츠) · ← 프로젝트 보드 상태: 사이클 1 착수 대기(10/05) · 3종 빌드 + 1종 대기 날짜는 QD 예산에서 계산 — 직접 고치지 않는다
배경 — 퀵게임 개발자는 전원 본업이 따로 있다. 그래서 이 프로젝트는 일정표보다 "얼마만큼의 시간을 쓰고, 언제 접느냐"를 먼저 정한다. 아직 공통 기반(템플릿·체크리스트)이 없으므로 첫 두 달은 적응기(30%), 이후는 정착기(50%)로 운영한다. 10/02 결정: 첫 사이클은 A안(30%를 전부 타이틀에 투입)으로 돌고, 10/05(월) 착수, 이상훈 님은 한붓그리기 → 로켓 X 순으로 진행한다. 사이클 1이 끝나면 회고로 규칙을 고친다.

1. 시간 규칙

#규칙내용
T1예산 단위 = QDQD(퀵게임 작업일) 1 = 8시간. 서비스 버전까지 예산 22 QD — "풀타임 30일"(달력 30일 ≈ 근무일 22일) 환산. 달력 날짜는 QD에서 계산하는 결과일 뿐이다
T2투입 비율적응기 10/05~11/27(8주) 30% = 주 12시간 = 주 1.5 QD → 정착기 11/30~ 50% = 주 20시간 = 주 2.5 QD
T3덩어리로 쓴다적응기: 화요일 종일 + 목요일 오후(14시 데모데이 포함) · 정착기: 화·수 종일 + 목요일 오후. 매일 조금씩 나눠 쓰지 않는다 — 몰입 회복 비용으로 실제 진척이 절반쯤으로 떨어진다
T4본업 마감 주는 정지본업 마일스톤 목표일이 걸린 주는 퀵게임 블록을 쉰다. 쉰 주는 QD가 쌓이지 않을 뿐 규칙 위반이 아니다 — 달력 날짜만 뒤로 밀린다. 정지는 데모데이에서 미리 신고
T5사용 QD 자기 신고매주 데모데이에서 타이틀별 "예산 22 / 사용 n"을 신고하고 3장 표에 누적한다. 진척률보다 이 숫자가 판단 근거다
T61인 1타이틀빌드 단계 타이틀은 한 사람당 하나. 다음 타이틀은 앞 타이틀이 서비스 버전에 도달하거나 Kill된 뒤 착수한다
T7예산 소진 = 재판정22 QD를 다 쓰고도 서비스 버전이 없으면 총괄이 재판정한다 — Kill(보관) · 범위 축소 · 추가 예산 중 하나. Kill된 타이틀은 지우지 않고 "보관"으로 둔다

계산 예: 10/05 착수 → 적응기 8주 × 1.5 = 12 QD(11/27) → 남은 10 QD ÷ 2.5 = 4주 → 12/24(목) 서비스 버전. 12/25 성탄절은 금요일이라 화·수·목 블록에 영향 없음. 정착기에 새로 착수하는 타이틀은 22 ÷ 2.5 ≈ 9주.

2. 파이프라인 단계 · 관문

단계예산나가는 조건
S0 아이디어—게임 카드 1장(핵심 루프 · 플랫폼 · BM · 레퍼런스와 시장 수치 · IP · 예상 QD) → 데모데이 발표 자격
S1 데모3 QD플레이 가능한 빌드로 데모데이 시연. 사이클 1의 4종은 10/01에 데모 완료로 본다
G1 범위 확정총괄 결정22 QD 안에 들어오는 범위로 확정 → 빌드 착수. Go / Hold / Kill
S2 빌드22 QD매주 데모데이 진척 시연 · 사용 QD 신고. 서비스 버전 = 처음부터 끝까지 플레이 가능 + 저장·설정 등 기본 기능 + 크래시 없음
G2 출시 판정총괄 결정출시 경로별 체크리스트(스팀 / 모바일 / 미니게임 플랫폼) · 등급 · IP 권리 확인
S3 출시 · 측정출시 +14일지표 리뷰(위시리스트·판매·리텐션) → 후속 업데이트 또는 보관

러브룰렛 「모니터룸」 FMV(전병모·안국주)는 영상 소스에 의존하고 규모가 달라 이 관문과 QD 예산을 따르지 않는 별도 트랙이다 — 별도 R&R 문서로 관리하고 데모데이에서는 진척만 공유한다.

3. 사이클 1 타이틀

#타이틀개발단계QD (사용/예산)서비스 버전 예상G1 범위 확정 조건 · 메모
Q1한붓그리기
이국마 국밥재료 퍼즐		이상훈빌드 대기0 / 2212/24 (+1주 제안)자사 웹툰 IP(이세계 국밥 마스터) 활용 · 이상훈 님 1순위. 착수 주(10/05~)는 신데렐라 런칭(10/09)과 겹쳐 T4 정지 대상 → 실제 착수 10/12, 서비스 버전 12/31경(연휴 고려 1/7 데모데이 확인)
Q2체스 서바이벌이순형빌드 대기0 / 2212/24발표 시 예상 풀타임 2~3개월(≈43~65 QD) → 22 QD 범위로 축소가 G1 조건(예: 1인 생존 모드 단일, 멀티·증강 일부는 후속). 본업(결 M2 10/23, 컨슈머 플랫폼 마무리) 정지 주 신고
Q3블랙잭 세븐변경호 본부장빌드 대기0 / 2212/24발표 시 "한 달" → 22 QD 안. 사업부 소속이라 30%/50% 비율 적용 여부 합의 필요 제안 · 카드 카지노류 — G2에서 등급·사행성 검토
Q4로켓 X이상훈보관(2순위)— / 223/4경T6에 따라 한붓그리기 서비스 버전 후 착수(1월 첫 주 예상) → 정착기 50% 기준 약 9주. 데모가 2일 만에 만들어진 만큼 G1에서 예산을 22보다 줄일 여지 제안

4. 사이클 1 마일스톤 — 날짜는 1장 계산에서 나온 값. QD 신고가 쌓이면 재계산한다

#마일스톤시작일목표일담당 / 확인완료 판정 기준
M1퀵게임 데모데이 1회차 ✅ 완료—10/01전병모완료(10/01) — 5종 발표(FMV 포함) · 데모데이 매주 진행 결정
M2사이클 1 착수 · 적응기(30%) 시작—10/05전병모[기준: 10/02 결정] 화·목 블록 개시, 각 타이틀 게임 카드 1장 제출
M3G1 범위 확정—10/08전병모[기준: 착수 후 첫 데모데이 제안] 타이틀별 22 QD 범위 확정 — 체스 축소안 · 블랙잭 비율 합의 포함
M4적응기 종료 점검 · 회고10/0511/26전병모 / 각 개발[기준: 적응기 8주 = 12 QD 사용 시점] 타이틀별 사용 QD 대비 진척 확인 · 규칙 보정 · 반복 작업 목록(공통 기반 후보) 정리
M5정착기(50%) 전환—11/30전병모[기준: 적응기 종료 다음 월요일] 화·수·목 블록 개시
M6서비스 버전 도달 (사이클 1)10/0512/24각 개발 / 전병모[기준: 12 QD + 10 QD ÷ 2.5 = 4주] 2장 S2 서비스 버전 정의 충족. 정지 주가 있었던 타이틀은 그만큼 뒤로(한붓그리기는 +1주 예상)
M7사이클 1 회고 · G2 출시 판정—1/07전병모 / 대표[기준: 연휴 후 첫 데모데이 제안] 타이틀별 출시 여부 결정 + 사이클 2 규칙 확정(시스템화 시간 별도 배정 여부 포함)

5. 데모데이 운영

  • 매주 목요일 14시 — 타이틀당 시연 5분 + 피드백 3분 + 사용 QD 신고. FMV는 진척 공유만.
  • 기록: 10/01 회의록 교정본 포맷(발표별 결정 · 확인 필요 · 레퍼런스)을 회차마다 그대로 쓴다. 같은 날 저녁 보드 갱신, 다음 날 금요일 주간회의로 이어진다.

6. 미결 · 확인

  • A안의 대가: 적응기 30%를 전부 타이틀에 쓰므로 공통 기반(유니티 스타터 · 출시 체크리스트 3종 · 스팀 개발자 페이지)을 만들 시간이 별도로 없다. M4 회고에서 "반복 작업 목록"을 뽑는 것으로 대신하고, 사이클 2에서 시간 배정을 다시 정한다. 공통 기반 담당 1인 지정은 남아 있다.
  • 이상훈 님 첫 주: 신데렐라 런칭(10/09) 주와 착수가 겹친다 — T4 정지로 한붓그리기 실제 착수 10/12 처리 여부.
  • 변경호 본부장 비율: 사업부 업무 기준으로 30%/50%를 그대로 적용할지.
  • IP · 등급: 이국마 IP 사용 범위 확인, 블랙잭 세븐 등급·사행성 검토(G2 전).
  • 데모데이 진행자: 지정 필요(순서표·기록 담당).
