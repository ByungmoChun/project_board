# 프로젝트 보드 — 새 채널 인수인계 (2026-09-30 기준)

> 이 문서를 새 채널 첫 메시지에 **zip과 함께 첨부**하고, 맨 아래 "시작 프롬프트"를 붙여 넣으면 이어서 운영할 수 있다.

## 0. 이 채널의 역할

- **슈퍼스토리 개발본부 전사 프로젝트 보드**의 운영 채널. 보드 갱신, 프로젝트별 R&R·마일스톤 문서 작성·수정, 주간 스냅샷만 다룬다.
- 운영자: 전병모(개발본부장, 내용 결정) + Claude(반영·정합 유지·스냅샷)
- 답변 언어: 한국어

## 1. 운영 방식 (확정)

- **도구**: 웹 보드(Vercel 정적 사이트). 노션은 쓰지 않는다. Jira는 안국주·홍수화가 관리하는 **실행 레이어**로 그대로 두고, 보드는 **포트폴리오 레이어**.
- **갱신 리듬**: 신규 건은 생기는 즉시 1분 등록 / 정기 갱신은 **목요일 저녁**(전병모 → Claude "보드 갱신:" 지시) → **금요일 주간회의** 안건 1번 "보드 훑기". (월요일 회의는 금요일로 이전됨)
- **주간 스냅샷**: 목요일 갱신 때 그 주 상태를 날짜 찍어 보관. 첫 회차 **10/1(목)**.
- **지시 형식 예시**
  ```
  보드 갱신:
  - 신데렐라 v1.3.1 Android 제출 완료, 수정 2건은 ○○·○○
  - 아이스크림 회신 옴, 다음 액션 미팅 일정, 팔로업 10/8
  - 신규: ○○○ 문의 (D, 오너 미정)
  ```

## 5. 문서 작성 규칙 (반드시 유지)

1. 마일스톤 표는 `# / 마일스톤 / 시작일 / 목표일 / 담당·확인 / 완료 판정 기준`. **시작일·목표일 둘 다** 적는다(인원별 R&R이 이 구간에서 파생).
2. **날짜 칸에는 날짜만.** 산정 규칙은 판정란 맨 앞 `[기준: …]` 태그. 모르면 ■.
3. 완료는 이름 옆 ✅ + 판정란에 완료일·경위. 단발 판단은 시작일 "—".
4. 버전이 바뀌어도 마일스톤을 새로 만들지 않는다 — 대상 버전만 갱신, 이력은 버전 로그.
5. 버전 로그: 제출하는 순간 행 생성 / 교체 버전은 비고에 종결 / 출시일 = 서비스 개시일(rollout 시작일) / 퀄리티업 지시는 다음 버전 행 비고에 누적.
6. **번호를 바꾸면 문서 내부와 보드·인원 카드의 M번호 참조를 모두 같이 고친다.**
7. 보드 행이 바뀌면 인원 카드(담당 중 / 임박 / 최근 완료)도 같이 맞춘다.
8. 주차 일정표 환산: **1주차 = 9/28(월)~10/02(금)**.
9. 새 R&R 문서는 신데렐라 문서 CSS·구조를 복제하고, 보드 행 상세 칸에 링크, README 파일 구성·작성 대상·변경 이력 갱신.
